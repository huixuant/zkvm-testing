# zkVM Miscompilation Test Cases

This directory contains small Jolt zkVM test cases for exploring how Rust compiler miscompilation bugs can affect proved execution. Each test case is a standalone Rust/Jolt program with a guest computation and a host prover/verifier, laid out as `<rust-issue>/<test-case>/`.

Every case is a *synthetic but realistic* workload: the miscompiling code pattern is embedded in an application shape where that pattern would plausibly be written (a settlement rule, a policy check, an inference kernel), rather than in a bare reproducer. Each `guest/src/lib.rs` opens with a header comment recording what the program models, which code pattern triggers the bug, and the security impact of the divergence.

The table below summarises the intended correct result and the result produced when the relevant compiler bug is triggered. All cases pin the 1.94 toolchain in `rust-toolchain.toml`; run one with `cargo run --release` from its directory.

| Rust issue | Test case | Path | What it models | Correct result | Buggy/miscompiled result |
| --- | --- | --- | --- | --- | --- |
| [#111502](https://github.com/rust-lang/rust/issues/111502) | Two-key vault | `111502/two-key-vault` | A 2-of-2 multisig vault that recomputes a request's `approved` bit from both signatures, writes it back, and reads it back to decide whether to release funds. | Output is `0`: with only one signature the recomputed bit is `false`, so access is denied. | Output is `0x8000_0000_0000_1388`: the by-value bundle is wrongly deduced `readonly`, so the read-back returns the record's stale `approved = true` and the funds are released without 2-of-2 approval. |
| [#113407](https://github.com/rust-lang/rust/issues/113407) | Emission guard | `113407/emission-guard` | Block-reward minting under a decaying emission schedule, where the committed per-block rate is narrowed `f64 -> f32` and compared against zero to decide whether emission has ended. | Output is `0`: the subnormal rate flushes to `0.0`, so nothing is minted. | Output is `50000`: `rustc_apfloat` mis-rounds the const-folded narrowing cast to a non-zero subnormal, so block rewards are minted past the end of the schedule. |
| [#127286](https://github.com/rust-lang/rust/issues/127286) | Quantised weight | `127286/quantised-weight` | Quantised on-chain ML inference, dispatching between weight-storage formats through a `TypeId`-guarded `dequant` primitive. | Output is `0x0000_1398` (5016): the `i8` weight is not an `(i8, i8)`, so the guard declines and the scalar path runs. | Output is `0x0`: LLVM mishandles the `undef` bytes of the never-taken out-of-bounds read and folds the guard away, and the `undef`-tainted result collapses to zero — a value the correctly compiled function cannot return at all (its `Some` arm always sets bit 31, its `None` arm always yields `5016`). |
| [#130853](https://github.com/rust-lang/rust/issues/130853) | Settlement guard | `130853/settlement-guard` | A rollup settlement step with an idempotent fast path: a change-detector decides whether to commit the recomputed state root or reuse the cached one. | Output is `0x00A1_1CE0`: the settlement wrote a new state byte, so the change is detected and the post-settlement root is committed. | Output is `0x00B0_0B00`: MIR GVN value-numbers the two dereferences of the shared reference as equal and folds the post-call re-read to the pre-call value, so an applied debit is committed under the stale cached root. |
| [#131195](https://github.com/rust-lang/rust/issues/131195) | Quorum auth | `131195/quorum-auth` | A governance/multisig executor that auto-executes an action only when a proposal class's standing delegation already covers all 32 signer seats (`!mask == 0`). | Output is `0`: the treasury class has only 8 of 32 seats pre-delegated, so the action is held for live signatures. | Output is `0x8800_0777`: JumpThreading treats the bitwise `!` as boolean and folds the saturation test to `mask != 0`, so a partial delegation is read as full board coverage and the action fires under quorum. |
| [#132353](https://github.com/rust-lang/rust/issues/132353) | k-NN nearest classifier | `132353/knn-nearest-classifier` | Privacy-preserving k-NN inference: candidates are popped from distance buckets in ascending order and combined into a distance-weighted vote. | Output is `3`: the five nearest labels vote 8-5-2 in favour of class 3. | Output is `0`: GVN reuses the cached dereference load across the dereference store in `pop_nearest`, so `Some(candidate)` is corrupted to `None`, the vote is empty, and the argmax falls back to class 0. |
| [#135941](https://github.com/rust-lang/rust/issues/135941) | AMM price scale | `135941/amm-price-scale` | A constant-product AMM TWAP oracle that recovers the price's binary exponent from a bit-length difference (the `num-rational` `Ratio::to_f64` reduction) and republishes it in Q32. | Output is `34359738368` (`1 << 35`): the window's exponent is 3, so the Q32 price is `2^32 << 3`. | Output is `18446744073709551615` (`u64::MAX`): the samesign implied-condition miscompile folds the `magnitude <= isize::MAX` check to false inside the taken branch, so a valid window is reported as an out-of-range magnitude and the oracle publishes its saturating guard. |
| [#137646](https://github.com/rust-lang/rust/issues/137646) | Rollup settlement | `137646/rollup-settlement` | A rollup account balance update where a declared credit is processed through a settlement rule selected by dynamic dispatch. | New balance is `1001`: opening balance `1000` plus declared credit `1`. | New balance becomes `1001000`: the by-value argument to the virtual call is wrongly deduced `readonly`, so the rule's normalisation (`credit *= 1_000_000`) leaks back into the caller's record and the proof certifies an over-crediting state transition. |
| [#143491](https://github.com/rust-lang/rust/issues/143491) | Keystream cipher | `143491/keystream-cipher` | A stream-cipher-style computation where a 1-bit feedback register drives the keystream used to encrypt a committed message. | Output digest is `1505719557`: the keystream bit is read before the register is clocked, giving the alternating stream `0,1,0,1,…`. | Output digest is `1414107962`: CopyProp folds the register's backing cell into its next state, so the register fails to advance on the first iteration and the keystream lags one step behind (`0,0,1,0,1,…`), desynchronising every ciphertext word from the second onward. |
| [#147265](https://github.com/rust-lang/rust/issues/147265) | Merkle sibling proof | `147265/merkle-sibling-proof` | An 8-level Merkle inclusion proof verifier that resolves each sibling through a `#[cold]` helper returning the pointer unchanged, then checks the computed root against the committed one. | Output is `true`: the walk reproduces the committed root `0xaf73_144e_668a_e4ca`. | Output is `false`: LLVM misoptimises the `Result` discriminant check on the cold call, so either a wrong sibling is read or the `Err` branch is spuriously taken, and a genuine membership proof is rejected — or, with a prover-chosen commitment, a wrong root is proven instead. |
| [#150904](https://github.com/rust-lang/rust/issues/150904) | Range credential | `150904/range-credential` | A DeFi lending credential check: KYC type, age, loan-to-value ratio, and income floor, folded into one mutated boolean. | Output is `0`: the borrower is rejected because LTV is `80_000` bps, far above the `7_500` bps cap. | Output is the nullifier `0x5c8e_80a7_aabe_500f`: `SimplifyComparisonIntegral` traces the `SwitchInt` back to the `cred_type == 1` constant comparison and drops the later `ok &= …` clauses, so the LTV cap and income floor are never checked and the invalid borrower is accepted. |
