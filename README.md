# zkVM Miscompilation Test Cases

This repository contains small Jolt zkVM test cases for exploring how Rust compiler miscompilation bugs can affect proved execution. Each test case is structured as a standalone Rust/Jolt program with a guest computation and a host prover/verifier.

The table below summarises the intended correct result and the result produced when the relevant compiler bug is triggered.

| Rust issue                                                 | Test case                       | Path                          | What it models                                                                                                              | Correct result                                                                                      | Buggy/miscompiled result                                                                                                                                                         |
| ---------------------------------------------------------- | ------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [#137646](https://github.com/rust-lang/rust/issues/137646) | Rollup settlement               | `137646/rollup-settlement`    | A rollup account balance update where a declared credit is processed through a settlement rule.                             | New balance is `1001`: opening balance `1000` plus declared credit `1`.                             | New balance becomes `1_001_000`: the credit is incorrectly treated as `1_000_000`, so the proof certifies an over-crediting state transition.                                    |
| [#143491](https://github.com/rust-lang/rust/issues/143491) | Keystream cipher                | `143491/keystream-cipher`     | A stream-cipher-style computation where a 1-bit feedback register drives the keystream used to encrypt a committed message. | With the checked-in adjusted final word, output digest is `1414107962`.                             | The keystream becomes desynchronised, so the digest is computed over the wrong ciphertext stream. With the checked-in adjusted input, the desynchronised digest is `1505719557`. |
| [#143491](https://github.com/rust-lang/rust/issues/143491) | Turn-based scoring              | `143491/turn-based-scoring`   | A two-player turn-based scoring system where players alternate turns over 32 moves.                                         | Output is `9223372036854776032`, meaning P1 wins by `224` points.                                   | Output becomes `224`, meaning the score is attributed to P0 instead; the proof certifies the wrong winner.                                                                       |
| [#147265](https://github.com/rust-lang/rust/issues/147265) | Merkle sibling proof            | `147265/merkle-sibling-proof` | An 8-level Merkle inclusion proof verifier that combines a leaf with sibling hashes to compute a root.                      | Computed root is `0x5e5c81c6a6e7b0bf`.                                                              | The sibling pointer/result handling is corrupted, producing `0` or an incorrect Merkle root while the zkVM proof still verifies that incorrect computation.                      |
| [#150904](https://github.com/rust-lang/rust/issues/150904) | Range credential                | `150904/range-credential`     | A DeFi lending credential check: KYC type, age, loan-to-value ratio, and income floor.                                      | Output is `0`: the borrower is rejected because LTV is `80_000` bps, far above the `7_500` bps cap. | Output is a non-zero nullifier, e.g. `0x5c8e80a7aabe500f`, meaning the invalid borrower is accepted.                                                                             |
| [#150904](https://github.com/rust-lang/rust/issues/150904) | Transaction signature pre-check | `150904/verify_tx_signature`  | A transaction signature component checker that rejects invalid scalar components before producing a sigcheck commitment.    | Output is `0`: the signature is rejected because `s == 0`.                                          | Output is a non-zero sigcheck commitment, e.g. `0x298fbb56da34ae57`, meaning a degenerate signature is accepted.                                                                 |
